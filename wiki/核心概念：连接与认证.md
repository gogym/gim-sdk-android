# 核心概念：连接与认证

`ImClient` 负责 TCP 长连接的全生命周期：连接、首包认证、读线程拆包、心跳驱动、指数退避重连、顶号处理。`GimImService` 是其对外封装。

## 连接状态机 ImConnectionState

```
DISCONNECTED ──connect()──▶ CONNECTING ──TCP建立──▶ CONNECTED ──BIND_RESP(code=0)──▶ AUTHENTICATED
      ▲                            │                        │                             │
      └────── 达到最大重连次数 ─────┴────── 心跳超时/断连 ────┴──────▶ RECONNECTING ───────┘
```

| 状态 | 含义 |
|------|------|
| `DISCONNECTED` | 未连接（主动断开或达到最大重连次数） |
| `CONNECTING` | 正在建立 TCP 连接 |
| `CONNECTED` | TCP 已连通，尚未认证 |
| `AUTHENTICATED` | 绑定成功（认证通过），可正常收发 |
| `RECONNECTING` | 断连后自动重连中 |

状态变更既通过 `ImClient.onStateChanged` 回调，也汇总到 `GimImService.connectionState: StateFlow<ImConnectionState>`。

## 首包认证流程

```kotlin
service.connect(ImConfig(host, port, userId, token, device, deviceId))
```

1. `connect()` 保存凭证，重置计数/标志，递增 `connectGeneration`，切 `Dispatchers.IO` 执行 `doConnect()`。
2. TCP 连接建立（`CONNECT_TIMEOUT_MS = 10s`），状态置 `CONNECTED`，启动读线程。
3. 立即发送 `BindRequest`（`cmd=BIND_REQ`，携带 userId/token/device/deviceId）。
4. 服务端回 `BindResponse`：
   - `code == 0`：记录 `serverId`，状态置 `AUTHENTICATED`，启动 `HeartbeatManager`。
   - 否则：触发 `onBindFailed(code, message)`，状态回到 `DISCONNECTED`。

> `deviceId` 是客户端**持久化 UUID**，服务端据此区分"同设备重连"与"异设备顶号"。

## 读线程与拆包

读线程 `ImClient-ReadThread`（daemon）持续 `inputStream.read`：

- 每次读到的字节追加到缓冲，循环调用 `FrameCodec.decode` 解出所有完整帧。
- 不足一帧的残余保留到下次读取（处理 TCP 粘包/拆包）。
- 每帧 `PacketCodec.decode` 还原 `Packet` 后交 `handlePacket`。
- 读到 EOF 或异常且未 `disposed` 且 `generation` 匹配时，触发 `handleDisconnect()`。

`handlePacket` 内部处理 `BIND_RESP`/`KICK_NOTIFY`/`HEARTBEAT_RESP`，其余 `Packet` 透传给 `onPacket`。

## 心跳

连接认证后 `ImClient` 创建并启动 `HeartbeatManager`（详见 [心跳与自动重连](消息能力：心跳与自动重连)）。收到 `HEARTBEAT_RESP` 时调用 `heartbeatManager.onHeartbeatResponse()` 重置超时窗口。心跳超时则关闭 Socket 并触发重连。

## 自动重连（指数退避）

`handleDisconnect()` 在未 `disposed`、未 `kicked` 时调用 `scheduleReconnect(generation)`：

```kotlin
delay = min(reconnectBaseDelayMs * 2^attempts, reconnectMaxDelayMs)   // 前台
delay = 5 * 60 * 1000L                                               // 后台（省电）
```

- `maxReconnectAttempts == null` 表示无限重连。
- 每次重连前 `reconnectAttempts++` 并 `PacketCodec.resetSequence()`。
- 重连成功后 `attempts` 归零。

**并发防护**：`reconnectScheduled` 保证同一时刻只有一个排队重连任务（防止多连接触发服务端同设备互踢形成重连风暴）；`connecting` 互斥保证同一时刻只有一个连接建立过程；`connectGeneration` 让旧的 disconnect/读线程退出不会误伤新连接。

## 顶号与踢下线

服务端下发 `KICK_NOTIFY`（同类型设备互踢等场景）时，`handleKickNotify`：

1. 置 `kicked = true`，停止心跳。
2. 回调 `onKicked(code, message)`（透传到 `ImEventListener.onKicked`）。
3. 关闭 Socket，状态置 `DISCONNECTED`。

被踢后自动重连被禁止；用户可主动调用 `reconnectIfNeeded()`（会重置 `kicked`）再次尝试，服务端基于 token 校验决定接受与否。

## 前后台

```kotlin
service.pauseForBackground()          // onStop：置 backgrounded，重连切 5 分钟低频
lifecycleScope.launch {
    service.reconnectIfNeeded()       // onStart：若已断开立即探活重连
}
```

## 主动断开与释放

```kotlin
service.disconnect()   // suspend：停心跳、重置序号、中断读线程、关 Socket，置 DISCONNECTED
service.dispose()      // 释放 client 与监听器列表（页面彻底销毁时）
```

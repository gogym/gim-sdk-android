# 消息能力：单聊与群聊

本文说明客户端消息收发、投递反馈（送达/已读/撤回）、在线状态与好友/群组通知的使用方式。所有消息通过 `PacketCodec` 构建、`GimImService.send` 发送，收端在 `ImEventListener` 中解析。

## 单聊

```kotlin
val packet = PacketCodec.buildSingleChatMsg(
    requestId = UUID.randomUUID().toString(),   // 幂等：匹配 ServerAck
    senderId = myUserId,
    receiverId = peerUserId,
    contentType = ContentType.TEXT.value,
    content = "你好",
    conversationId = "conv_$myUserId$peerUserId",  // 可选
    ext = mapOf("nick" to "Alice"),                // 可选
)
service.send(packet)   // chatType 内部固定为 1
```

收到对端消息触发 `onMessageReceived`：

```kotlin
override fun onMessageReceived(packet: ImProto.Packet) {
    val msg = PacketCodec.parseChatMessage(packet)
    // msg.senderId / receiverId / contentType / content / msgId / conversationId / ext
}
```

## 群聊

```kotlin
val packet = PacketCodec.buildGroupChatMsg(
    requestId = UUID.randomUUID().toString(),
    senderId = myUserId,
    receiverId = groupId,          // 群 ID
    contentType = ContentType.TEXT.value,
    content = "各位好",
    conversationId = groupId,
)
service.send(packet)   // chatType 内部固定为 2
```

同样在 `onMessageReceived` 中接收，通过 `msg` 的 `chatType`（1/2）区分单聊/群聊。

## 内容类型 ContentType

| value | 类型 | 推送文本 |
|-------|------|---------|
| 1 | TEXT 文字 | [消息] |
| 2 | IMAGE 图片 | [图片] |
| 3 | AUDIO 语音 | [语音] |
| 4 | VIDEO 视频 | [视频] |
| 5 | FILE 文件 | [文件] |
| 6 | LOCATION 位置 | [位置] |
| 7 | CUSTOM 自定义 | [自定义消息] |
| 8 | CALL_RECORD 通话记录 | [通话记录] |

图片/语音/文件等富媒体：`content` 承载 URL 或资源标识，尺寸/时长等放入 `ext`（`Map<String,String>`）。

## 投递反馈

### SERVER_ACK（发送成功）

服务端收到消息后立即回执 `ServerAck`（分配 `serverMsgId`），触发 `onMessageSent`。客户端可用 `requestId` 幂等匹配本地待发送消息，将状态从"发送中"更新为"已发送"。

### DELIVERY_ACK（已送达）

接收方收到消息后可回传送达确认：

```kotlin
service.send(PacketCodec.buildDeliveryAck(msgId = msg.msgId, senderId = msg.senderId))
```

原发送方在 `onMessageDelivered` 中收到，展示"已送达"。

### READ_RECEIPT（已读）

```kotlin
// 单聊必传 receiverId（服务端直接转发给对方）；群聊留空
service.send(PacketCodec.buildReadReceipt(conversationId, lastReadMsgId, receiverId = peerUserId))
```

对方在 `onMessageRead` 中收到已读回执。

### 撤回 MSG_RECALL

```kotlin
// 单聊必传 receiverId；群聊留空（服务端向全群下发）
service.send(PacketCodec.buildMsgRecallReq(
    msgId = msgId,
    conversationId = conversationId,
    chatType = 1,            // 1 单聊 2 群聊
    requestId = UUID.randomUUID().toString(),
    receiverId = peerUserId,
))
```

相关方在 `onMessageRecalled` 中收到 `MSG_RECALL_NOTIFY`，据 `msgId` 撤下本地消息。

## 在线状态

服务端推送 `ONLINE_STATUS_NOTIFY`，客户端按 `status`（1=在线，0=离线）分派到 `onUserOnline` / `onUserOffline`：

```kotlin
override fun onUserOnline(packet: ImProto.Packet) {
    val notify = PacketCodec.parseOnlineStatusNotify(packet)
    // notify.userId / status ...
}
```

## 好友与群组通知

| 事件 | 回调 | payload 解析 |
|------|------|-------------|
| 好友申请 | `onFriendRequest` | `parseFriendRequestNotify` |
| 好友状态变更 | `onFriendStatusChanged` | `parseFriendStatusNotify` |
| 群成员变更 | `onGroupMemberChanged` | `parseGroupMemberNotify` |
| 群信息/事件 | `onGroupNotify` | `parseGroupNotify` |
| 入群申请 | `onGroupJoinRequest` | `parseGroupJoinRequestNotify` |

这些通知仅传达"发生了什么"，具体好友/群组数据由业务侧根据通知回源查询与落库。

## 设计边界

- **SDK 不落库**：收到消息后如何持久化、去重、排序、未读计数由使用方实现。
- **可靠投递在服务端**：自动重发、离线消息由服务端（gim-sdk-java）保证；客户端专注收发与状态展示。
- **幂等**：以 `requestId`（发送）与 `msgId`（接收）作为幂等键，避免重复处理。

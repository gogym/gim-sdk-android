# 核心概念：事件监听与消息收发

`GimImService` 是对外唯一入口：封装 `ImClient`，把收到的 `Packet` 按 `cmd` 分发到 `ImEventListener` 回调，并暴露 `StateFlow` 供 UI 观测。SDK 只负责通信层，落库/UI 由使用方实现。

## GimImService API

| 方法 | 说明 |
|------|------|
| `addEventListener(listener)` / `removeEventListener(listener)` | 注册/移除事件监听 |
| `suspend connect(config: ImConfig)` | 连接并首包认证 |
| `suspend disconnect()` | 主动断开 |
| `suspend reconnectIfNeeded()` | 回前台/手动重连探活 |
| `pauseForBackground()` | 进入后台，暂停高频重连 |
| `send(packet: ImProto.Packet)` | 发送任意 Packet |
| `val isAuthenticated: Boolean` | 是否已连接并认证 |
| `val userId / serverId: String?` | 当前用户 ID / 服务端节点 ID |
| `val connectionState: StateFlow<ImConnectionState>` | 连接状态流 |
| `dispose()` | 释放资源并清空监听器 |

一个 `GimImService` 可注册多个 `ImEventListener`，事件会分发给所有监听器。

## 事件分发映射

`GimImService.dispatchToListener` 依据 `packet.cmd` 调用对应回调：

| cmd | 回调 | 解析建议 |
|-----|------|---------|
| `SINGLE_CHAT_MSG` / `GROUP_CHAT_MSG` | `onMessageReceived` | `parseChatMessage` |
| `SERVER_ACK` | `onMessageSent` | `parseServerAck` |
| `DELIVERY_ACK` | `onMessageDelivered` | `parseDeliveryAck` |
| `READ_RECEIPT` | `onMessageRead` | `parseReadReceipt` |
| `MSG_RECALL_NOTIFY` | `onMessageRecalled` | `parseMsgRecallNotify` |
| `ONLINE_STATUS_NOTIFY` (status=1/0) | `onUserOnline` / `onUserOffline` | `parseOnlineStatusNotify` |
| `FRIEND_REQUEST_NOTIFY` | `onFriendRequest` | `parseFriendRequestNotify` |
| `FRIEND_STATUS_NOTIFY` | `onFriendStatusChanged` | `parseFriendStatusNotify` |
| `GROUP_MEMBER_NOTIFY` | `onGroupMemberChanged` | `parseGroupMemberNotify` |
| `GROUP_NOTIFY` | `onGroupNotify` | `parseGroupNotify` |
| `GROUP_JOIN_REQUEST_NOTIFY` | `onGroupJoinRequest` | `parseGroupJoinRequestNotify` |
| `RTC_SIGNAL` | `onRtcSignal` | `parseRtcSignal` |
| `RTC_GROUP` | `onRtcGroupSignal` | `parseRtcGroup` |

连接类事件直接回调：`onConnectionStateChanged`、`onKicked`、`onBindFailed`。

> `BIND_RESP`、`HEARTBEAT_RESP`、`KICK_NOTIFY` 由 `ImClient` 内部消化，不作为普通消息透传（心跳响应仅重置超时窗口，`KICK_NOTIFY` 转为 `onKicked`）。

## ImEventListener

`ImEventListener` 是 `open class`，所有回调默认空实现，按需覆盖：

```kotlin
class MyListener : ImEventListener() {
    override fun onMessageReceived(packet: ImProto.Packet) {
        val msg = PacketCodec.parseChatMessage(packet)
        // 入库 / 刷新会话列表 / 未读数
        // 需要回执"已送达"时：
        service.send(PacketCodec.buildDeliveryAck(msg.msgId, msg.senderId))
    }

    override fun onMessageSent(packet: ImProto.Packet) {
        val ack = PacketCodec.parseServerAck(packet)
        // 依据 requestId / serverMsgId 更新本地消息状态
    }

    override fun onConnectionStateChanged(state: ImConnectionState) {
        // 更新连接指示灯
    }

    override fun onKicked(code: Int, message: String) {
        // 被顶号，提示并返回登录页
    }
}
```

## 观测连接状态（协程 / Compose）

```kotlin
// View: lifecycleScope
lifecycleScope.launch {
    repeatOnLifecycle(Lifecycle.State.STARTED) {
        service.connectionState.collect { render(it) }
    }
}

// Compose
val state by service.connectionState.collectAsStateWithLifecycle()
```

## 发送模式

SDK 只暴露 `send(packet)`，业务通过 `PacketCodec` 构建 `Packet` 后发送。这样保持通信层薄壳、协议构建集中且可测。

```kotlin
val packet = PacketCodec.buildGroupChatMsg(
    requestId = UUID.randomUUID().toString(),
    senderId = service.userId!!,
    receiverId = groupId,
    contentType = ContentType.IMAGE.value,
    content = imageUrl,
    ext = mapOf("w" to "1080", "h" to "1920"),
)
service.send(packet)
```

## 线程模型

- `send` 是**线程安全**的（`synchronized`），非阻塞；Socket 不可用时仅记录日志并丢弃（对齐 Flutter `Socket.add` 行为），断连由读线程自然检测后触发重连。
- 事件回调在**读线程**上触发，UI 更新需自行切主线程（或借助 `StateFlow` + `repeatOnLifecycle`）。
- `connect` / `disconnect` / `reconnectIfNeeded` 为 `suspend`，内部对阻塞 I/O 切 `Dispatchers.IO`。

# 架构概览

GIM Android SDK 是 GIM IM 体系的**客户端通信层**，与 [gim-sdk-java](https://github.com/gogym/gim-sdk-java) 服务端协议一一对应。本文说明 SDK 的分层、数据流与关键设计取舍。

## 分层结构

```
┌──────────────────────────────────────────────────────────────┐
│                        使用方 App 代码                         │
│   GimImService.connect(...) / send(...)  ·  ImEventListener   │
├──────────────────────────────────────────────────────────────┤
│                     对外服务与事件层                           │
│   GimImService（连接入口 · StateFlow · 事件分发）             │
│   ImEventListener（消息/通知/信令/状态回调）                 │
├──────────────────────────────────────────────────────────────┤
│                       音视频能力层                             │
│   RtcEngine（1:1 通话状态机 + offer/answer/ICE）             │
│   GroupRtcEngine（群通话生命周期信令 cmd=51）                │
│   MeshGroupTransport（P2P 多路） · SfuGroupTransport（LiveKit）│
├──────────────────────────────────────────────────────────────┤
│                       连接与传输层                             │
│   ImClient（TCP Socket · 读线程 · 指数退避重连 · 顶号处理）  │
│   HeartbeatManager（单线程心跳 + 超时检测）                  │
│   FrameCodec（Varint32 拆包/粘包）                           │
├──────────────────────────────────────────────────────────────┤
│                       协议与模型层                             │
│   ImProto（Protobuf Lite 生成） · PacketCodec · Cmd           │
│   ContentType · DeviceType · ImConfig                        │
└──────────────────────────────────────────────────────────────┘
```

## 包职责

| 包 | 关键类 | 职责 |
|----|--------|------|
| `core` | `ImClient`、`HeartbeatManager`、`FrameCodec`、`ImConnectionState` | TCP 长连接、读线程拆包、心跳调度、指数退避重连、顶号处理 |
| `protocol` | `ImProto`、`PacketCodec`、`Cmd`、`ContentType`、`DeviceType` | Protobuf 信封的构建与解析、命令号与内容类型常量 |
| `service` | `GimImService` | 对外唯一入口，封装 `ImClient`，按 `cmd` 分发事件，暴露 `StateFlow` |
| `spi` | `ImEventListener` | 事件回调扩展点（open class，覆盖关心的方法） |
| `model` | `ImConfig` | 连接地址、认证信息、心跳/重连参数 |
| `rtc` | `RtcEngine`、`RtcTypes` | 1:1 WebRTC 通话的信令状态机与媒体管理 |
| `rtc.group` | `GroupRtcEngine`、`GroupMediaTransport`、`MeshGroupTransport`、`SfuGroupTransport`、`GroupRtcDto`、`GroupRtcTypes` | 群通话生命周期信令 + Mesh/SFU 媒体传输工厂 |

## 数据流

### 接收

```
Socket 读线程 → FrameCodec.decode（Varint32 拆帧）→ PacketCodec.decode（Protobuf）
   → ImClient.handlePacket（BIND_RESP/KICK/HEARTBEAT_RESP 内部处理）
   → GimImService.dispatchToListener（按 cmd 分派）
   → ImEventListener.onXxx(packet)
```

### 发送

```
PacketCodec.buildXxx(...) → GimImService.send → ImClient.send
   → PacketCodec.encode（Protobuf 序列化）→ FrameCodec.encode（加 Varint32 长度前缀）
   → Socket.getOutputStream().write
```

### 音视频信令

```
IM 事件 onRtcSignal/onRtcGroupSignal → RtcEngine.handleSignal / GroupRtcEngine.handleGroupSignal
引擎需发信令时 → callback.onSendSignal / onSendGroupSignal → service.send(...)
Mesh 点对点媒体信令：onRtcSignal → GroupRtcEngine.handleMediaSignal → MeshGroupTransport
```

## 关键设计取舍

- **通信层纯净**：SDK 不落库、不生成 UUID、不做 UI，业务与通信彻底解耦。
- **单线程心跳**：`HeartbeatManager` 用单线程 `wait/notify` 串行"发送—等响应—休眠"，规避 `java.util.Timer` 任务复活导致的误超时。
- **代次隔离并发**：`connectGeneration` + `reconnectScheduled` + `connecting` 三标志协同，杜绝并发连接触发服务端同设备互踢形成重连风暴。
- **前后台省电**：后台重连切 5 分钟固定间隔，回前台立即探活。
- **WebRTC 全局复用**：`PeerConnectionFactory` 与 `EglBase` 全局创建、单次通话不释放，硬件编解码工厂挂载，避免协商失败与 EGL 割裂。
- **Mesh/SFU 工厂化**：`GroupRtcEngine` 依 `roomState.mode` 选择传输实现，生命周期信令与媒体通道彻底分离。
- **信令缓冲**：transport 未就绪时缓冲对端 offer/answer/ICE，就绪后重放，防止"双方互等"卡连接中。
